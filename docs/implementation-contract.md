# AgentPay implementation contract

AgentPay is an original single-agent governed treasury prototype. GenLayer interprets the financial mandate; Aevum independently enforces deterministic payment restrictions. The executor is trusted to attest to finalized semantic approval; it cannot exceed the vault limits. No cross-chain proof is claimed.

## Shared interfaces

All amounts are decimal strings in tUSD8 (6 decimals) at HTTP boundaries; bigint base units internally. Aevum chain ID 44005, token 0x456569838f1d43009A91ebA4263147Afd7233483, HTTPS RPC https://rpc-test.qday.info, explorer https://explorer-test.qday.info. Treasury IDs are vault addresses. Policy versions are positive integers; mandateHash is keccak256(UTF-8 text).

PaymentRequest: id (bytes32), treasuryId, agentId (bytes32), policyVersion, recipient, amount, service, purpose, evidence (plain text), createdAt, expiresAt, idempotencyKey. Stored payment adds amountUnits, requestHash, decision reference/reason, execution transaction hash, status, attempts, leaseUntil. Lifecycle: queued, evaluating, awaiting_finality, approved, rejected, needs_information, executing, settled, expired, failed. Submitted settlement is reconciled before any resubmission.

API envelopes: {success:true,data} or {success:false,error:{code,message}}. Agent endpoints: GET /api/v1/treasury, GET /api/v1/policy, POST /api/v1/payments, GET /api/v1/payments, GET /api/v1/payments/:id. Bearer credentials are random opaque keys, hashed at rest, scoped to one active agent/treasury/key version. Owner login uses nonce-bound wallet signatures and HttpOnly SameSite cookies. Authenticated owner setup/controls are under /api/owner. Rate limits must persist across instances and fail closed in live mode. Evidence is bounded plain text; no arbitrary URL fetching.

Repository interface separates durable storage, policy evaluation, and settlement. Owner approved MongoDB Atlas free-tier as the live durable store. Demo mode is explicit and isolated, uses a local file store for request persistence and deterministic simulation; it never presents simulation as real GenLayer consensus or Aevum settlement. Live mode requires complete config, fails closed, and never falls back to demo execution.

Vault required functions: constructor(token, owner, executor); configureAgent(agentId, policyVersion, mandateHash, perPaymentLimit, weeklyBudget, totalBudget, validUntil, recipients); revokeAgent(agentId); setPaused(bool); setExecutor(address); withdraw(recipient, amount); executePayment(requestId, agentId, policyVersion, recipient, amount, approvalExpiresAt, requestHash, decisionRef). Expose executed(requestId), agentConfig(agentId), isRecipientAllowed(agentId,address), available budget views, and token/owner/executor/paused. Use UTC Unix weeks floor(timestamp / 604800); budgets count only actual settled payments, cannot be reset by policy updates; policy version increases strictly. Positive amounts, approved recipients, supported token only, epoch binding, expiry and replay enforced. Payment events include all request/agent/version/recipient/amount/decision references. Withdrawals are owner-only, work while paused, and never reset spending accounting. Owner emergency pause/revoke invalidates pending execution. No agent key can withdraw.

GenLayer contract is authored independently. Store immutable mandate text keyed by treasury/agent/version and write decision records keyed by requestId, binding request hash and mandate hash. Only the configured governance operator registers policies and submits evaluations. Evaluate request service/purpose/evidence semantically using independent validator judgment over stable approve/reject/needs_information fields plus grounded explanation. Defensively validate model output; invalid outputs fail closed. No GenLayer funds movement. Use current documented SDK finality and runner pin, then lint.

Worker runs bounded batches on GitHub hosted runners, with scheduled reconciliation and manual dispatch. Use durable claim leases, persisted signed transaction hash before broadcast, pending transaction/receipt reconciliation, and serialized signer nonces. No private key in browser, source or logs. Vercel handles short API/UI requests. Optional dispatch token stays server-only. Live mode has no demo keys.

UI uses original navy/blue ledger workspace, readable white surfaces, mandate panel, payment review ledger, service catalog demonstration, decision timeline, owner funding/withdraw/pause/revoke controls and explicit demo/live badges. Include desktop/mobile, keyboard, validation, empty/loading/error states. No controls without functional action; owner live actions require wallet signatures and chain checks. Use plain CSS, React and viem; no mandatory account abstraction or payment provider.

Root owns shared config and integration. Worker ownership is listed in .unlazy/agentpay/PLAN.md. Each worker writes tests first and must record the observed red state, verify its complete deliverable, review errors/security, and run appropriate checks. Do not alter another worker's files.
